## Stripe Billing (Web Only)

- `farm_comps` is service-managed, soft-delete-only billing metadata with a membership-checked status RPC. A live comp is the owner farm's complimentary access. There is no trial countdown. Do not turn on access enforcement. There is no in-app purchase. The US-storefront website link in `PlanUpgradeLink` is separate and must stay. Comp grants are excluded from customer restore and Ask the Book; owner recovery classifies them separately. `billing_audit_log` is service-role-only (RLS on, no client policies) and records farm_comps insert, update, and soft_delete via a SECURITY DEFINER trigger; there is no DELETE trigger. See BLUEPRINT below for schema/audit details.

- There is no trial. Do not stamp trial dates or pass Stripe `trial_end`. `20261109210000_remove_trial.sql` stopped `ensure_user_farm` from writing them. The old `trial_claims` table and columns remain unused and stay out of customer backup and restore. History only: a 3-month trial was designed and then removed (`docs/free-tier-handoff.md`).

Canonical detail: [BLUEPRINT → Stripe Billing](../../BLUEPRINT.md#stripe-billing-web-only).

- Stripe checkout and the customer portal are web-only, and hidden unless `VITE_BILLING_UI_ENABLED === 'true'`. `isBillingUiAvailable` is false on Capacitor, so the Stripe card does not render there. The US App Store storefront website link (`PlanUpgradeLink`, `docs/ios-storefront-link.md`) is deliberate and must stay; every other storefront has no link. That plan card renders only when `entitlement.enforced` is true. The legal pages are reachable in the native app, so on Capacitor `Terms` section 4 shows only its approved iOS line and `Refund` omits the Settings → Billing step and the Stripe mention (`LegalPolicies.test.tsx` covers it); keep any new price or billing wording out of the native render. Production `ENTITLEMENTS_MODE` is `enforce` since 2026-11-16 (a fresh database defaults to `off`); do not change it without the owner. The rollout allowlist is server-only (`BILLING_ALLOWLIST`): required in Vercel production (the bundle check can still require a non-empty `BILLING_ALLOWLIST`), optional with a warning elsewhere. Test mode still uses the allowlist (empty or unset fails closed). Live mode opens checkout to every authenticated web owner without blanking `BILLING_ALLOWLIST`. The Settings card asks `GET /api/billing-eligibility` with the caller's bearer token and never reads `VITE_BILLING_ALLOWLIST`.
- Live charges are allowed only when `BILLING_LIVE_CHARGES` is exactly `true` (trim, case-insensitive) and `STRIPE_SECRET_KEY` is an `sk_live_` key. Otherwise the flag stays absent or exactly `false` and the server accepts only `sk_test_` keys. The webhook ignores (200, `mode_mismatch`) any event whose `livemode` differs from the deployment's mode and writes `farm_subscriptions.livemode`. An `active` row is Pro only through `current_period_end` + 14 days (`_farm_entitlement`, `getFarmBillingAccess`). **Live cutover checklist:** live `STRIPE_WEBHOOK_SECRET` and `STRIPE_PRICE_ID`; attorney sign-off; then, as service role, retire test rows: `UPDATE public.farm_subscriptions SET deleted_at = now() WHERE livemode IS NOT TRUE AND deleted_at IS NULL` (check the count first; rows from before 2026-11-21 have `livemode` NULL).
- Production `ENTITLEMENTS_MODE` is `enforce` since 2026-11-16 (a fresh database defaults to `off`); do not change it without the owner. In `off`, a missing or soft-deleted subscription row is `unmanaged` with full access. Do not let absent billing data become a paywall.
- Under the installed Stripe SDK (API `2025-08-27.basil`) `current_period_end` lives on subscription **items**, not the Subscription; use `resolveCurrentPeriodEnd` (`server/billing.ts`). Build webhook tests from the basil shape.
- Customer tiers are Free and Pro. The app is a permanent free record book; Pro is $299 per farm per year. Say "Pro" in app strings (`src/copy/entitlements.ts`). One account per farm. No ads. Production `ENTITLEMENTS_MODE` is `enforce` since 2026-11-16 (a fresh database defaults to `off`); do not change it without the owner. (`off | shadow | enforce` live in `entitlement_config`.) The server decides (`farm_entitlement`, `assert_premium` raising `P0402 premium_required:<feature>`); the client (`useEntitlement`) only displays. Code plans are `free | paid | complimentary`; complimentary is the owner farm only, not a sold tier. Free limits that are real: 50 active fields, and rainfall daily totals on the farm's two oldest fields, which are locked (`rainfall_field_hourly_allowed` gates explicit-field `mrms-backfill`). SQL returns `photo_cap` NULL (`20261110190000_entitlements_hardening.sql` replaced 20), `history_seasons` 2, and `device_cap` 1. Those are not live limits (no photo capture, history cap not enforced, one-device limit not built). FSA/CLU data entry (tract import, CLU assignment, FSA farm/tract/field numbers) is free (`20261116120000_fsa_entry_free.sql`). Pro: all-field hourly rainfall, grain bins, equipment, landlord splits, backup restore, prepared reports (FSA-578, crop insurance production, spray, fertilizer, Hay Summary, landlord summaries; `PAID_REPORT_TYPES` in `src/lib/entitlements.ts`), and cattle events, head transfers, and the cattle CSV ([docs/agents/cattle.md](./cattle.md)). Nothing is deleted on downgrade. Export of the farm's own logged data stays available. Prepared Pro report save, share, print, and CSV/PDF export call `assert_premium` and fail closed. `RAIN_API_AUTH` is not enforcing; do not set it to `enforce`. The app may send a Supabase bearer token (`RainService`). Handoff: `docs/free-tier-handoff.md`.
- Checkout is refused (409, use the portal) for a live `trialing`/`active`/`past_due`/`unpaid` subscription; only `canceled`/`incomplete` rows may start a new Checkout. Checkout never sets a Stripe `trial_end` (the old farm-deadline pass-through was removed 2026-11-09). An existing `stripe_customer_id` is reused.
- `farm_subscriptions` is written only by the signed webhook (service role). Clients never trust query parameters or client-reported Stripe state.
- Billing tables stay out of the customer JSON backup and stay classified in the owner recovery registry.
